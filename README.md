# KADR · Kamera-UD

**Демо для заказчика (ЖК):** https://davydovserg.github.io/Kamera-UD/

Своя видеоаналитика KADR. Клиент даёт доступ к камерам или регистратору, мы подключаем их в панели, включаем нужные сценарии, и события сразу уходят на почту или в Telegram.

- Сообщение содержит только текст: время, камеру и сценарий. Видео клиент смотрит у себя.
- Кадры и видео на диск **не сохраняются**. Журнал отправок хранится 30 дней (`data/journal.db`).
- Детектор — YOLOX-S (лицензия **Apache-2.0**, можно использовать в закрытом коммерческом продукте) через onnxruntime. Работает на CPU, при наличии CUDA использует GPU.

## Сценарии

| Сценарий | Что делает | Что нарисовать |
|---|---|---|
| Человек в зоне | человек/машина в зоне; с часами — «нерабочее время», без часов — всегда (крыша, забор) | зону |
| Опасная зона | человек на крыше, в техзоне, котловане, проезде паркинга — всегда, тревога через 2 с | зону |
| Вдоль забора | человек идёт вдоль ограждения или стоит у него дольше N с; просто пересечь полосу — не тревога | полосу вдоль забора |
| Стоянка в запрещённой зоне | машина стоит в зоне дольше N минут | зону |
| Заезд / выезд | счёт машин через линию ворот, сообщение на каждый проезд и/или сводка за день | линию |
| Сводка погрузок | грузовик стоит в зоне погрузки ≥ N мин; вечером приходит список «погрузка — камера — 14:32 (25 мин)» | зону |
| Исправность камеры | камера не в сети, картинка зависла, закрыта или темно; отдельное сообщение при восстановлении | — |
| Огонь | открытое пламя: базовый режим (цвет + мерцание) работает сразу, обученная модель `models/fire.onnx` подхватывается, если положить | зону (необязательно) |
| Номера машин | чтение номеров (fast-alpr, MIT), журнал, сверка со списком жителей, сообщения о чужих | зону |
| Вынос | человек выходит через линию с сумкой, техникой или крупным предметом в руках | линию (стрелка = «туда») |

Наборы по типу объекта (включаются при добавлении камеры):
- **ЖК**: огонь, стоянка, номера, опасная зона, вдоль забора, исправность.
- **Склад**: заезд/выезд, нерабочее время, погрузки, вынос, исправность.
- **Стройплощадка**: нерабочее время, заезд/выезд, исправность.

> **Точность — проверять на камерах клиента.**
> - Огонь, базовый режим: ловит пламя по цвету и мерцанию, статичные лампы и фары отсекает. Может пропустить маленький огонь или сработать на мигалку. Для ЖК лучше обучить модель (YOLOX, классы `fire, smoke`, датасет D-Fire + негативы с объекта) и положить в `models/fire.onnx`.
> - Номера: модели скачиваются при первом включении (~12 МБ). Номер нужен от 120 px в ширину, угол камеры до 30°, ночью — ИК-подсветка.
> - Вынос: видит предметы из COCO (сумка, рюкзак, чемодан, техника, мебель) и «широкий силуэт». Коробку как отдельный предмет не распознаёт.

## Запуск

```bash
pip install -r requirements.txt
python scripts/download_models.py     # yolox_s.onnx, 35 МБ
python run.py                         # config.yaml создастся из примера
```

Панель: `http://<сервер>:8080`, логин `admin`, пароль задаётся в `config.yaml` → `panel.password` или переменной `KADR_PANEL_PASSWORD`. **Пароль поменять сразу.**

Docker:

```bash
KADR_PANEL_PASSWORD=секрет docker compose up -d --build
```

Конфиг и журнал объекта лежат в `./site`.

## Как подключать клиента

1. От клиента нужны: внешний IP или домен регистратора, проброшенный порт RTSP (обычно 554), логин и пароль **только на просмотр**.
2. В панели нажмите «+ Регистратор»: укажите производителя (Hikvision, Dahua, Trassir, Uniview), адрес и диапазон каналов, выберите тип объекта. Камеры добавятся все сразу.
   Если камера одна или у неё нестандартная ссылка, нажмите «+ Камера», вставьте RTSP-ссылку и нажмите «Проверить связь».
3. Откройте камеру, включите сценарии и нарисуйте прямо на кадре зону или линию. Сохранение применяется сразу, без перезапуска.
4. Во вкладке «Уведомления» укажите почту клиента (SMTP) и/или Telegram-бота, затем нажмите «Отправить проверку».

Для анализа используйте второй поток камеры (substream): шаблоны Hikvision и Dahua по умолчанию берут именно его.

## Нагрузка

По умолчанию каждая камера анализируется 1 раз в секунду (`detector.interval_sec`). YOLOX-S на CPU обрабатывает кадр примерно за 50–150 мс, так что один современный CPU держит около 8–15 камер. Для 50 камер нужен GPU: поставьте `onnxruntime-gpu`, движок подхватит CUDA сам.

## Как добавить сценарий

`kamera/scenarios.py`: создайте класс с `@register`, укажите `key`, `title`, `needs` (`zone`/`line`/None), список полей `params` и метод `process(ctx)`, который возвращает тексты событий. Панель покажет новый сценарий сама.

## Структура

```
run.py                точка входа (движок + панель)
kamera/detector.py    YOLOX ONNX
kamera/tracker.py     трекер по IoU (id объекта, время в кадре, путь)
kamera/camera.py      чтение RTSP с переподключением, шаблоны регистраторов
kamera/scenarios.py   сценарии и наборы по типу объекта
kamera/engine.py      потоки анализа по камерам
kamera/notify.py      почта, Telegram, журнал 30 дней
kamera/web.py         API панели
kamera/static/        панель (один HTML)
```

## Обучение модели огня (train/)

1. `train/dfire_to_coco.py <dfire_yolo>` — D-Fire (CC0, 21 527 кадров) → COCO, классы fire, smoke.
2. Из клона YOLOX: `python tools/train.py -f train/exp_fire.py -d 1 -b 16 --fp16 -c yolox_tiny.pth` (переменные DFIRE, EPOCHS).
3. `python tools/export_onnx.py -f train/exp_fire.py -c best_ckpt.pth --output-name models/fire.onnx` — сценарий «Огонь» подхватит модель сам.

На RTX 3050 Laptop одна эпоха ≈ 20 мин (30 эпох ≈ 10 ч); быстрее на облачной GPU.
`train/make_demo.py` — прогоняет модели по кадрам для демо-страницы.
